# SEO audit — agent playbook

Read **Operating rules** and **Repo map** before touching anything. Then pick
tasks by `status`. Do not start a task whose status is `NEEDS-*` without the
missing input; the input column says exactly what is missing.

## Operating rules

1. **Never push to `main`.** Every push to `main` deploys to production. Work on a branch, open a PR, let the Vercel preview build.
2. **Never hand-edit `work/*.html`, the card grid in `portfolio.html`, the rail in `index.html`, or `sitemap.xml`.** They are generated. Edit `data/projects.json`, `templates/**` or `build.js`, then run `node build.js` and commit the generated output.
3. **Never invent numbers, quotes, client names or results.** This site sells measured results. If a task needs a figure, it is `NEEDS-CONTENT`: stop and ask.
4. **Headline numbers are decided** (README.md, "Content status"): ₹1 Cr+, 60+ brands, 400+ trained, 37K+ Instagram. Make everything else agree with them; do not change them.
5. **Canonical host is `https://kajalandani.co`** (`SITE` in `build.js`). It is not live yet; the site currently serves from `kajalandanico.vercel.app`. Do not "fix" canonicals to the vercel.app host.
6. Run `python3 -I .agents/seo-audit/verify.py` before every commit. It must print `all checks passed`.
7. Commit trailer for this repo's AI-authored commits: `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.

## Applied

### SEO-01 · Footer legal links 404 on case-study pages · P0 · APPLIED
- **Evidence:** `templates/partials/footer.html` linked `privacy-policy.html`, `terms-of-use.html`, `cookie-policy.html`, `disclaimer.html` with no `{{base}}`, so on `/work/x.html` they resolved to `/work/privacy-policy.html`. Confirmed live on `blythe-living-seo` and `deage`.
- **Change:** prefixed the four links with `{{base}}`; rebuilt all 16 pages.
- **Accept:** `verify.py` check SEO-01 (1,021 internal references, 0 broken).

### SEO-02 · Staging host was indexable · P0 · APPLIED-UNVERIFIED
- **Evidence:** live `robots.txt` on `kajalandanico.vercel.app` was `Allow: /`; no meta or header noindex; canonicals point at the not-yet-live `.co`.
- **Change:** `vercel.json` now sends `X-Robots-Tag: noindex, nofollow` when the host matches `.*\.vercel\.app`.
- **Why host-scoped:** a global noindex would deindex production the day `kajalandani.co` is attached. `verify.py` fails if the rule is ever not host-scoped.
- **Consequence to know:** until `kajalandani.co` is attached (SEO-10), nothing on this project is indexable. That is intended.
- **Accept after deploy** (cannot be tested locally; Vercel also adds noindex to preview URLs, so test the production alias):
  `curl -sI https://kajalandanico.vercel.app/ | grep -i x-robots-tag` returns the header; `curl -sI https://kajalandani.co/` returns none. If the deploy rejects the regex in `has.value`, replace it with the literal `kajalandanico.vercel.app`.

### SEO-08 · Structured data · P1 · APPLIED
- **Already present (earlier chat audit could not see it; its fetch strips `<script>`):** `ProfessionalService` with `founder` and `sameAs` on `index.html`; `BreadcrumbList` on every case study via `templates/partials/head.html`.
- **Added:** `Person` (Kajal Andani, Founder, `worksFor` → org `@id`, `sameAs` Instagram + LinkedIn) on `about.html`; `Service` (`provider` → org `@id`) on the three service pages. Facts come only from existing page copy.
- **Do not add:** `Review`/`AggregateRating` for the on-site testimonials (self-hosted reviews earn no rich result and invite a manual action); `FAQPage` for rich results (restricted to a narrow set of sites since 2023).
- **Accept:** `verify.py` SEO-08; then paste each URL into Google's Rich Results Test once live.

### SEO-06 · Case-study titles and descriptions · P2 · APPLIED
- **Before:** `"<headline> | <client> | Kajal & Co."`, 85–100 chars, led with generic phrasing nobody searches. Descriptions up to ~190 chars.
- **After:** `"<Client>: <Service> Case Study | Kajal & Co."`; when over 60 chars, drops "Case Study". Descriptions trimmed at a word boundary to ≤158 chars. The long headline remains the on-page H1.
- **Follow-up (optional, NEEDS-CONTENT):** hand-write `metaDescription` per project in `data/projects.json`; trimmed statements read adequately but not persuasively.
- **Accept:** `verify.py` SEO-06.

### SEO-03 · Redundant label · P2 · APPLIED
"SEO Search Engine Optimization" appeared in the nav, mobile sheet, and contact form on every page. Replaced with "SEO"; the `seo.html` eyebrow now reads "Search Engine Optimization". Form `value="seo"` is unchanged, so the Apps Script pipeline is unaffected.

### SEO-04 · Homepage URL consistency · P2 · APPLIED
Logo and footer links pointed at `index.html` while the canonical is `/`. Now `./` (root pages) and `{{base}}./` (templates). `404.html` was left alone; it already uses root-absolute paths.

### SEO-05 · Sitemap honesty · P2 · APPLIED
Every build stamped all URLs with the build date, and `priority` is ignored by Google. Both removed in `build.js`. Re-add `<lastmod>` only with the true last-changed date of each page (a Vercel checkout has no per-file history to read it from).

### SEO-07 · robots.txt · P3 · APPLIED
Removed `Disallow` lines and the comment naming `/case-studies/`, `/tools/`, `/content/`, which are not deployed. Kept `/templates/` and `/data/`, which are served.

## Open: P0

### SEO-10 · Production domain is not attached · NEEDS-DECISION
- **Evidence:** Vercel project `kajalandco` lists only `*.vercel.app` domains. Canonicals, `og:url`, `og:image`, JSON-LD and the sitemap all use `https://kajalandani.co`. Social previews and canonical consolidation cannot work until it resolves. The audit's fetch tool was blocked on `kajalandani.co`, so its live state is unverified.
- **Decisions needed (human):**
  1. Attach `kajalandani.co` to project `kajalandco` and set DNS.
  2. Decide what happens to the existing `kajalandani.com` site and its equity. The client brief names `.com` as her current website. Recommended: 301 every `.com` URL to its nearest `.co` page; keep `.com` registered.
- **Agent steps once decided:** add the domain (Vercel `add_project_domain` / dashboard), `verify_project_domain`, add `.com` redirects in `vercel.json` `redirects` (host-scoped with `has`), confirm `curl -sI https://kajalandani.co/` is 200 with no `X-Robots-Tag`, then submit `https://kajalandani.co/sitemap.xml` in Search Console.
- **Accept:** `.co` returns 200; `view-source` canonical equals the requested URL on 5 sampled pages; `.com` URLs return 301 to `.co`.

### SEO-11 · Contradictory stats baked into images · NEEDS-ASSET
- **Evidence (from image alt text; view the files before editing):** `assets/img/about-graphic.webp` is described as "37K+ Instagram followers, 20+ trusted brands, ₹1 Cr+ revenue" and `assets/img/about-story.webp` as "100+ students mentored and 30+ clients served". The decided numbers are 60+ brands and 400+ trained. Hero stats on the same site say 60+ / 400+.
- **Why it matters:** a studio whose pitch is "honest advice" publishes two different answers to "how many brands". Text inside images is also uncrawlable.
- **Needs:** re-export both graphics from the design masters (`Visual Assets/`, gitignored, not in the repo) with the decided numbers, then update the `alt` text to match.
- **Accept:** every number in image text and alt equals the README list; `grep -rn "20+\|30+ clients\|100+ students" *.html` returns no stat claims.

### SEO-12 · Blythe Living SEO case study fails scrutiny · NEEDS-CONTENT
Entry: `slug: blythe-living-seo` in `data/projects.json`.
- The section headed "Before, and after" shows only values labelled **Baseline**; no before figure exists.
- The copy says 789 organic sessions produced 46 purchases (≈5.8% organic conversion on high-ticket furniture) while "4.4K tracked users" is total traffic. Either the attribution wording is wrong or the claim will not be believed.
- It advertises deploying `AggregateRating` schema. Without genuine on-site review data that is a guideline violation, not a selling point.
- **Needs (client GA4 export, from whoever ran the SEO):** organic sessions and organic-attributed purchases, before and after, same date ranges. Then rewrite the metric blocks and the "Business impact" copy to say only what the export supports.
- **Do not** soften by guessing a split. If data is unavailable, remove the purchase-attribution sentence and the `AggregateRating` claim, and relabel the section "Results".
- **Accept:** every figure on the page traces to a labelled export; "Baseline" labels either carry a real before value or are gone.

### SEO-14 · Entity and positioning · NEEDS-DECISION
- **Facts:** the homepage `<title>`, `<h1>` and meta description never contain "Kajal Andani" (it appears in an H2 and the schema). The audience searches the person (37K Instagram followers). The site speaks as "we / studio / three specialists" while the client brief says solo practitioner, "not an agency".
- **Options:** (a) person-led: title `Kajal Andani | Website Design, SEO & Performance Marketing`; (b) studio-led, keep as is and rely on schema; (c) hybrid: keep `Kajal & Co.` in the title, add "by Kajal Andani" to the H1 eyebrow and meta description.
- **Recommendation:** (c). It captures name searches without contradicting the studio copy. It is a positioning call for the consultant and the client, so an agent must not choose.
- **Accept:** chosen wording appears in `<title>`, meta description, and Open Graph/Twitter tags on `index.html`, and matches `about.html`.

### SEO-15 · Thin service pages, no internal links to proof · NEEDS-CONTENT
- `seo.html` is roughly 250 words; FAQs are one line each; no service page links to its case studies.
- **Build plan (mechanical once copy exists):** add `<!-- build:related-work -->` markers to the three service pages and a `build.js` `inject()` call that renders `templates/partials/work-card.html` for `projects.filter(p => p.service === '<key>')`. Reuse the existing card styles from the portfolio grid; check it at 375px and 1280px on the Vercel preview before merging.
- **Copy needed per page (150–300 words):** who it is for, what is fixed first, what a month looks like, one concrete example. Needs the specialists' input; do not generate it generically.

### SEO-16 · No content hub · NEEDS-CONTENT
The site has service pages and case studies only. For an SEO consultancy, its own ranking is the proof. Realistic targets are niche long-tail, not "website design". Candidate topics that the existing case studies can substantiate, each needing the client's real specifics: Shopify tag-URL index bloat, local SEO for a UK play centre, airport-transfer landing pages for taxi firms, Meta ads funnels for NCR real estate. Add an `/insights` index and put articles through the same `build.js` pipeline (new data file and template). Keep each article tied to a real engagement.

### SEO-17 · Testimonial balance · NEEDS-CONTENT
Of 8 homepage testimonials, 7 are about website or brand work (4 name only Aman, 3 name Aman and Kajal) and 1 (Blythe Living) covers SEO and performance marketing, naming Harsh and Kajal. The site sells three services as one integrated offer; the proof covers one. Add verifiable SEO and ads testimonials (name, role, company, link to a LinkedIn profile or case study).
